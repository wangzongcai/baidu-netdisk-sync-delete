# 双端同步删除

百度网盘的扩容占位文件（【柚子扩容】那一类）**只删一端不生效**，必须网页端和客户端把同一份文件都删掉才真正释放空间，而且两端删除动作的时间差越小越好。

这个工具干的就是这件事：**用毫秒级补偿让两端的「确定」几乎同时触发，并把两端的实际时间差测出来。**

## 核心思路

两端的链路长短差得很远：

```
网页端  点击 ──────[ 浏览器构造请求并发出 ]──────> 到服务器
               勾 8 个 ≈ 176 ms，勾 285 个 ≈ 928 ms

客户端  点击 ─[ 约 7 ms ]─> 到服务器
```

如果同时点，网页端的请求会晚到服务器几百毫秒。所以程序**先点网页端，等一段"提前量"再点客户端**，让两条请求撞在同一时刻。

提前量不是套公式算的，而是**查实测表**：同数量档位删过一次，就把「网页端本地段」记下来，下次直接用。

## 两个指标

日志最后会打一个结论框，里面是两个不同的数：

| 指标 | 含义 | 能不能调到 0 |
|---|---|---|
| ① 请求**发出**时刻差 | 两个删除请求离开本机的时刻差 | **能**，实测已到 +5 ms |
| ② 删除**生效**时刻差 | 两端各自看到「清理完成」的时刻差 | **不能**，受百度服务器调度支配 |

② 有天然下限，因为两端是两个独立 HTTP 请求，服务器每次给它们排的处理时间都不一样。批量越大越明显：勾 8 个时 ② 只有十几毫秒，勾 285 个时会被拖到几百毫秒。

## 怎么用

1. 网页端打开 <https://pan.baidu.com/disk/clear>，客户端打开「垃圾文件清理」
2. **两端各自手动勾选**要删的重复文件，点「删除」调出「确定」确认框
3. 运行程序，点「② 同步删除」
4. 看日志末尾的结论框

程序不代劳勾选，也不弹二次确认——核对通过就直接执行。

## ⚠ 警告

**这个工具会真实删除文件，不可逆。** 它不提供「试运行」以外的任何保护：点下去就是真删。请先确认你勾中的确实是要删的重复/占位文件。

## 环境要求

- Windows（用到 `PrintWindow`、`PostMessageW` 等 Win32 接口）
- Microsoft Edge
- 百度网盘客户端，且已登录
- 源码运行需要 Python 3.12 + `playwright`、`Pillow`、`numpy`

打包版不需要装 Python，但 **`_internal` 目录必须和 exe 放一起**。

| 文件 | 作用 |

## 已知坑

- **网页端列表是扫描缓存**。删完之后那些行不会消失，只是头部计数变化，会出现「幽灵行」。必须点「重新扫描」才会刷新，否则下次全选会带上已经删掉的 `fs_id`。
- **客户端的「清理完成」不是独立小窗**，是整个主窗口换成了完成页（绿勾 + 释放空间数字）。检测完成时刻就是检测这个绿勾，不用去找小窗口。
- 客户端的「确定」不是标准控件，没有句柄，只能用截图找文字像素 + `PostMessageW` 投递点击。**不要用 `SetCursorPos` 走物理光标**：两端只有一个物理光标，两个线程会互抢，时间差反而从 0.2ms 退步到 1~2ms。
- 网页端的网络事件必须有 `page.wait_for_timeout()` 驱动才会派发，`time.sleep()` 不派发。
